# Windows release build

The build creates a self-contained x64 CPU application and a per-user Inno
Setup installer. Personal settings and results live in `%LOCALAPPDATA%/Tingji`,
outside the application directory. Uninstalling does not remove that directory.

Use the dedicated `work/windows-installer/build-venv` only. Install CPython 3.12
and create that venv without system site packages. Install the CPU wheels first:

```powershell
& work/windows-installer/build-venv/Scripts/python.exe -m pip install --index-url https://download.pytorch.org/whl/cpu torch==2.6.0+cpu torchaudio==2.6.0+cpu
& work/windows-installer/build-venv/Scripts/python.exe -m pip install -r requirements_windows.txt
```

Speaker analysis reads only the 16 kHz mono PCM16 WAV generated by the bundled
FFmpeg. Its standard-library WAV reader reads bounded blocks, so meeting length
does not determine audio memory use. SoundFile/libsndfile and its codec chain
are excluded from the Windows bundle. Keep them out of the build environment.

Obtain the redistributables from their official upstream sources. Review their
redistribution licenses and corresponding-source requirements before publishing.
Do not copy an installed Conda environment or the project directory wholesale.

The curated `work/windows-installer/vendor` layout is:

```text
3d-speaker/speakerlab/__init__.py
3d-speaker/speakerlab/models/__init__.py
3d-speaker/speakerlab/models/campplus/__init__.py
3d-speaker/speakerlab/models/campplus/DTDNN.py
3d-speaker/speakerlab/models/campplus/layers.py
3d-speaker/pretrained_models/campplus/campplus_cn_en_common.pt
ffmpeg/bin/ffmpeg.exe
ffmpeg/bin/ffprobe.exe
ffmpeg/bin/<matching LGPL shared-build DLLs>
licenses/<reviewed notices and license text>.txt
prerequisites/MicrosoftEdgeWebView2RuntimeInstallerX64.exe
```

Pin these files, then inspect the generated manifest. The build rejects files
outside the allowed vendor layout, changed hashes, junctions and symbolic links.

```powershell
& work/windows-installer/build-venv/Scripts/python.exe scripts/windows/prepare_vendor_manifest.py --vendor-dir work/windows-installer/vendor
& work/windows-installer/build-venv/Scripts/python.exe scripts/windows/build_windows.py --version 2.2.0 --iscc work/windows-installer/toolchain/inno/ISCC.exe
```

Only allowlisted, Git-tracked application sources, the built frontend and
branding assets become staging input. Dependency hooks run with a clean child
environment that excludes API credentials and user-specific model paths. Model
code and weights are copied only from the pinned vendor manifest.

The license input must cover the Python runtime and its dependencies (including
embedded native-library notices), all frontend production packages from
`web/package-lock.json`, shadcn component notices, and the bundled model's
official Apache 2.0 model card. PyInstaller's bootloader license exception also
accompanies the executables. Build tools themselves are not shipped.

`--stage-only` verifies and prepares input without freezing or compiling.
`--skip-freeze` recompiles the installer only when the prior frozen bundle's
input receipt exactly matches the current reviewed source and vendor inputs.

Before publishing, test `Tingji.exe --self-check <temporary-report-path>` using
a clean data profile. Install and launch the installer in an empty test target,
verify GUI, audio conversion, local speaker inference, exports and API behavior.
Never use private recordings or real API keys as packaged test fixtures. Run the
source publication guard and independently review the built file manifest.
The console helper supports the same check as `TingjiSpeaker.exe --self-check`;
the report exercises synthetic WAV conversion and reading, Silero inference,
and real CPU CAM++ model loading/inference, without inspecting saved app data.

The release directory contains the installer, SHA256SUMS, third-party notices
and a relative-path file manifest. No signing claim is made: the executable is
unsigned unless an explicitly configured signing process is added separately.
